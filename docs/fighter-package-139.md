# Separate fighter package

`npm run build:game` / `npm run build` writes `fighter-package/manifest.json` and 36 immutable payloads separately from the game build. Deploy the main build normally, but upload this package into the same backend BUCKET under `fighters/` before exposing the new game client. Upload access uses a temporary server-only `FIGHTER_MEDIA_UPLOAD_TOKEN`; unset it after verification. No secret is shipped to the client.

`python3 scripts/upload-fighter-media.py` reads a JSON object containing origin, token and siteAuth from hidden stdin. Do not pass credentials as shell arguments. It uploads each object, verifies byte ranges, downloads the complete object, and verifies SHA-256. Existing objects are never overwritten. The upload route itself validates the full SHA-256 filename against the received body. Credentials and live uploads are not part of the offline tests.

Measured by rerunning the previous packing algorithm, the main build previously held 147,405,671 bytes of model/clip/texture payloads; now it holds zero (plus the manifest URL mapping). The remote package has 18,155,700 more bytes than those old Float32-packed payloads because original clip encodings are retained.

The 36 model, animation and texture files occupy 165,561,371 bytes (157.89 MiB) in their original encoding. All are copied exactly, with full SHA-256 names. Previously the build repacked animation numbers into Float32 for smaller gzip output. This package instead preserves original clips bytes too; its transfer size is consequently larger than that old packed representation, but the main game no longer contains those payloads. Configs remain local gzip files (6,417,098 bytes combined) for immediate metadata loading. Source configs, models, clips, and textures are not edited. There is no texture quality reduction.

The existing sequential selected-pair loader and disposal behavior are retained. It loads only requested fighter payloads, releases models outside the selected pair, and deduplicates pending loads. All render code and animation timing remain unchanged. Source development uses local assets; production build replaces only the payload URL resolver with the immutable manifest mapping. Gzip is transported as `application/gzip` without Content-Encoding to preserve literal compressed bytes; the loader supports both explicit decompression and servers that already decoded gzip.

`node scripts/audit-fighter-asset-package.mjs` verifies every copied byte/hash, excludes payloads from main build, and verifies that loader code differs only by URL mapping. `node scripts/audit-fighter-media.mjs` tests auth, upload hashes, duplicate immutability, GET/HEAD/Range, conditional requests and literal gzip transport. These tests do not establish latency on real phones or successful live R2 uploads. Before release, run upload verification and test cold and warm selection of every pair on iPhone/Android, retry after interrupted transfer, and fight startup without network after cached assets.
